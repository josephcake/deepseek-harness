# Agent Note: 听写快捷键在按键松开时结束

Status: implemented

[English](2026-10-24-dictation-shortcut-hold-release.md) | 中文

## Problem

语音输入只能从麦克风按钮开始。启用听写 Bundle 的用户无法用键盘开始或停止录音，且快捷键服务只分发按下事件：按住说话命令没有可结束采集的事件。在插件内自行监听按键会绕过命令目录、冲突校验、用户绑定和各平台投递方式。

## Decision

已处理的 `ShortcutResolution` 可以返回 `release()`。注册表把解析出的操作与其触发按键或双键组合一起记录，并在最后一个键松开时调用 `release()`。双键组合中未触发操作的那个键松开时，只移除该键。窗口失焦和页面隐藏会释放所有按住中的操作。命令销毁会丢弃待完成的激活，不调用 `release()`；owner 的拆卸结束自己的操作。

Windows 和 macOS Desktop 将拦截过的每次按下对应的松开事件作为原生输入转发，复用可信 preload 通道，并且不按已接受的配置 revision 校验。Web 从 DOM 按键事件读取同一事实；Linux Desktop 的松开事件未被拦截，继续走 DOM 路径。

语音输入插件在 `ctx.effect()` 中注册可编辑的 `voice.dictate` 命令。Desktop 和 Web 的 macOS 默认 Command+Option+V，Windows 默认 Ctrl+Alt+V；Linux 各配置不设默认值，因为平台保留规则拒绝该组合。解析器优先选择主视图保留的 Session 所属输入框，其次选择最近挂载的输入框。Bundle 详情持久化浏览器本地的“触发方式”：按一次切换只调用一次 `run()`，按住说话返回 `run()` 和 `release()`。若麦克风授权尚未完成时收到松开，则推迟到采集开始后再停止。

## Alternatives considered

**在语音插件内监听原始按键事件。** 这会复制快捷键服务已拥有的物理键校验、冲突报告、用户覆盖和 Desktop 原生投递，绑定也不会出现在“键盘快捷键”中。

**为松开单独注册一个命令。** 命令需要针对实时目标解析操作；单独注册无法共享按下时解析出的目标，并会在按下与松开之间与重新绑定竞争。

**把触发方式存入 Host 语音设置。** 触发方式描述浏览器输入行为，而非识别本身。Host 往返会把本地键盘偏好耦合到识别 profile，并让无关 Session 等待设置写入。

## Consequences

快捷键服务的生命周期因此超出一次同步按下，适配器必须投递松开事件，命令 owner 必须保证 `release()` 可重复调用。Desktop 为每次拦截的按下多付一条 IPC 消息。Linux 配置没有默认绑定；命令仍出现在“键盘快捷键”中，用户可自行分配受支持的组合。触发方式随浏览器 origin 保存，而非 Harness profile，与麦克风选择一致。

验证覆盖单键、双键、重复、销毁、失焦和页面隐藏时的注册表释放；DOM 和原生适配器；Desktop 拦截转发；两种模式下注册的命令；输入框路由；授权期间的延迟停止；触发方式恢复；以及设置控件。
